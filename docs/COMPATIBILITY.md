Текущая stable — **2026.916.1**. В скользящее 30-дневное окно
2026-08-30…2026-09-29 входят четыре версии: 2026.916.1, 2026.916.0,
2026.831.1 и 2026.831.0. Все восемь комбинаций версии и режима прошли
[проверку совместимости в GitHub Actions](https://github.com/maljaev-alex/paperclip-ru/actions/runs/36498680277).
Для каждого официального пакета сверены npm integrity и точный отпечаток
`ui-dist`; пройдены `doctor`, dry-run, `apply`, `verify`, повторный `apply`,
браузерные маршруты в обоих режимах и byte-identical `revert`. Даты проверок
более старых версий сохранены отдельно и не означают повторный прогон 29 сентября.

Сентябрьский интерфейс дополнительно проверяет чаты агентов, подключение
каналов, разрешения, API-ключи и редакции инструкций. Фиктивный чат создаётся
без отправки сообщений и запуска агента; у связанной задачи есть план.
Редактор сравнивается с исходным UI той же версии, а пользовательские названия,
инструкции и Markdown сохраняются без перевода.

`full` означает чистую обязательную матрицу на официальной сборке. У
`2026.817.0` уровень `best-effort`, потому что её исходный frontend обращается к
отсутствующему в том же official package endpoint
`/api/companies/:id/built-in-agents` и получает 404. Ошибка воспроизводится без
русского overlay; все проверки перевода, panel-resize и точного отката прошли.
Фикстура `2026.831.1-synthetic` используется только в автономных тестах и не
считается официальной сборкой.

Windows и Linux: Node 20+ для paperclip-ru. Для запуска самого Paperclip
2026.831.x и 2026.916.x нужен Node 24.11+. macOS остаётся experimental: обязательная локальная
приёмка выполняется на Windows/Linux, а дополнительная CI-задача macOS допускает
ошибку и не считается подтверждением поддержки.

Несовпадение файлов с официальным отпечатком блокирует первый apply даже при
известном номере версии. `--force-baseline` — отдельное ручное исключение.
Обновление Paperclip требует `reapply`; обновление русификатора — `update`.
Новая версия инструмента может добавить поддержку сборки, которую старая версия
отклоняла. Перед заменой инструмента новый CLI доказывает совместимость.

Еженедельный workflow заново получает все stable-релизы за последние 30 дней и
проверяет каждый на отдельном сервере с тестовой базой в обоих режимах. Только
повторно подтверждённая ошибка создаёт issue. Workflow не меняет список
поддерживаемых версий и не принимает неизвестный fingerprint автоматически.
