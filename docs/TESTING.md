# Testing

## Быстрые проверки исходников

```sh
npm ci
npx playwright install --with-deps chromium --no-shell
npm run lint
npm test
npm run build
npm run compat:recent
git diff --check
```

`npm test` запускает все unit/integration/e2e файлы. В CI команда выполняется на Node 20 и 24.
Playwright и Chromium обязательны для e2e: отсутствие браузера даёт ошибку.
Проверки PowerShell и Windows path aliases выполняются в Windows; POSIX modes и
umask — в Linux. Пропуски этих платформенных тестов явно отмечаются в отчётах.
Полный POSIX lifecycle обязателен.
Для PowerShell 5.1 и 7 есть отдельные задачи CI.

Образы GitHub Actions закреплены: Ubuntu 24.04, Windows 2025 и экспериментальный
macOS 15 Intel. Имена обязательных проверок `windows-latest` / `ubuntu-latest`
сохранены для совместимости с защитой ветки; фактический образ задаётся отдельно.

`npm run lint` блокирует ошибки и каждое замечание вне точного baseline.
Ранее допущенные замечания выводятся отдельным счётчиком `accepted baseline
findings`; это не новые предупреждения и не подтверждение качества каждой
такой строки. `node tools/lint-dictionary.mjs --json` показывает все исходные
диагностики и причины допуска. Изменение перевода или сообщения проверки
аннулирует старое исключение, даже если число замечаний не увеличилось.

Unit проверяет AST-защиту, контракт CLI, словарь, безопасные пути, архивы и SVG.
Включены вычисляемые JS-ключи, литеральные `$`-токены в сгенерированном оверлее,
унаследованные имена `Object.prototype` и реальная Windows sharing violation.
Integration работает в каталогах `os.tmpdir()`: реальные старый/новый CLI,
install/update/uninstall, ошибки дочернего verify, прерывание процесса посреди
записи/переименования/удаления, точные inventory, права и время файлов после
rollback. Посторонние изменения после сбоя должны блокировать recovery до записи.
Отдельно проверяются двойной сбой операции/rollback, JSON исходного и частичного
состояния, приватные recovery-копии, сторонний chmod и Windows aliases одного
install root, включая журналы предыдущего RC.
Справочные флаги `--help`, `-h` и `--version` проверяются для каждой команды:
UI, install root и каталоги отчётов должны оставаться неизменными.
Fixture e2e проверяет DOM-контекст, редакторы, placeholder, native confirm,
сохранение пользовательских байтов, Intl, счётчики и опциональное изменение панелей.
Патч вкладки навыка «Обзор» после `/files/...` проверяется юнитом по сигнатуре бандла.
`panel-preference.test.mjs` проверяет чистую установку без ресайза, включение,
сохранение выбора при apply/reapply/dry-run и stale-манифесте, явное отключение
и отказ при противоречивых флагах. Это отдельная проверка от перетаскивания панели:
успех fixture drag не доказывает, что модуль включён в установленном Paperclip.

## Полный официальный сервер

Нужны Node 24.11+, браузер и отдельная локальная PostgreSQL-база, которую можно
изменять. Команда ниже скачивает зафиксированную official stable, устанавливает
её runtime-зависимости в temp, запускает свой сервер с отдельным `PAPERCLIP_HOME`,
отключённой телеметрией и планировщиком агентов. Создаются только фиктивные данные;
агент приостановлен. Существующая установка Paperclip не перезапускается.

```powershell
$env:PAPERCLIP_TEST_DATABASE_URL = "postgresql://postgres@127.0.0.1:5432/paperclip_release_test"
npm run test:official:isolated
```

Для POSIX задайте ту же переменную окружения перед командой. База не удаляется:
её жизненным циклом управляет вызывающий тестовый контур. В CI это временный
PostgreSQL service. После проверки сервер останавливается, UI откатывается и
сверяется с полным исходным inventory, временный runtime удаляется.

Результаты — `test-results/official/`: журналы, route-matrix, снимки экрана,
подтверждение revert. `PAPERCLIP_TEST_OUTPUT` меняет каталог вывода.
`PAPERCLIP_RU_DIST_DIR` включает установку из конкретного релизного архива: браузер
проверяет оверлей именно из этих байтов. `PAPERCLIP_TEST_VERSION` выбирает explicit
stable для проверки совместимости; неизвестная сборка безопасно отклоняется.
Если `doctor` отклонил неизменённую сборку, очистка сверяет полный исходный
inventory и не вызывает `revert`: в журнале остаётся первоначальная причина
отказа. Если файлы изменились, обязательны `revert` и побайтовое сравнение.

`PAPERCLIP_RU_PANEL_RESIZE=1` выполняет тот же gate с включённым модулем ширины
панелей: `apply` получает `--with-panel-resize`, gate сверяет `features` манифеста,
проверяет, что flagless `apply` сохранил выбор, и запускает `test/official/panels.test.mjs`
с настоящим pointer-drag. Если инспектор не смонтирован на первичном рендере, тест
открывает правый sheet (кнопка «Новая задача» и соседние) и падает, когда
классифицированной панели всё равно нет. Без переменной gate проверяет режим по
умолчанию и требует полного отсутствия handles и оверлейного stylesheet. Оба режима
нужно прогнать перед релизом: они проверяют разные ветки `apply`.

`npm run compat:recent` получает из npm перечень stable-сборок за последние 30
дней и сверяет его с `data/compatibility.json`: для каждой версии обязательны
дата фактической проверки, официальный fingerprint `ui-dist` и сохранённый npm
package integrity. Release workflow блокируется при любом расхождении и запускает
официальный gate для каждой версии в обоих режимах панелей.

## Браузерная матрица

`test/official/` требует явные `PAPERCLIP_TEST_BASE_URL` и `PAPERCLIP_SERVER_DIR`.
Не направляйте эти тесты на рабочую базу: seed меняет настройки тестового экземпляра.
`tools/routes.json` содержит общие маршруты, тест добавляет карточки созданных
задачи/проекта и страницы агента. Проверяются язык, title, видимая латиница,
aria/placeholder, ошибки, ширина 1440 и 390 px, reload с отключённым HTTP-кэшем.
Латиница проверяется также в смешанных русско-английских строках и после каждого
reload. Режим доски включается реальной кнопкой, наличие карточек проверяется.
Точные исключения: `test/helpers/route-allowlist.mjs` — бренды, команды, пути,
идентификаторы и заданные seed-данные. Неизвестная фраза блокирует gate.

Снимок первичного рендера не видит содержимое select, меню, поповеров и tooltip:
оно монтируется только на время открытия. Поэтому на каждом маршруте генератор
последовательно раскрывает disclosure-триггеры (`aria-haspopup`, `role="combobox"`),
снимает текст и `placeholder`/`aria-label`/`title` из портала и закрывает поверхность
через Escape. Триггеры с разрушающей подписью (удаление, отзыв, сброс) пропускаются.
Число раскрытых поверхностей на маршрут попадает в `routes[].surfacesSampled` и
`surfaceProbes` route-matrix — по нему видно, что покрытие меню действительно было,
а не подразумевалось. Утверждение «0 runtime leaks» без непустого `surfaceProbes`
относится только к первичному рендеру.

В official package `2026.817.0` frontend обращается к отсутствующему в том же
server package endpoint `GET /api/companies/:id/built-in-agents`; upstream
возвращает 404. Gate допускает только эту точную пару URL/ошибки и сохраняет её в
route-matrix. Любая другая ошибка браузера по-прежнему блокирует приёмку.

Редактор инструкций сравнивается с исходным official bundle в отдельном browser
context. Сверяются исходные CRLF/пробелы/JSON, отсутствие записи при открытии,
штатная защита после реального ввода и точные байты PUT-пayload. Сохранение в этом
тесте перехватывается до API, поэтому исходный файл остаётся неизменным.

Имена задач, агентов, компаний и проектов временно заменяются на словарные ключи
`Dashboard`/`Settings`. Проверяются список, доска, заголовки, breadcrumb,
переключатель компании и tooltip; исходные имена восстанавливаются через API.
Названия остаются английскими, соседние подписи интерфейса переводятся.
Для сентябрьских сборок и 2026.1001.0 проверяются также вложенное имя компании в
переключателе, контекстная ссылка агента, чат с агентом и подсказки исполнителя
на доске. Режим просмотра инструкций сначала переключается в редактирование;
доступность сохранения и точные байты запроса сравниваются с исходной сборкой.
Маршрутная матрица включает новые страницы разрешений, API-ключей, ревизий,
чата с агентом и настройки подключения чата. Экспериментальные чаты включаются
только в одноразовой тестовой базе, если сборка предоставляет такие настройки.

`/decisions/training` удалён из матрицы: такого маршрута в текущей stable нет.
`/design-guide` — служебный каталог компонентов upstream с демонстрационными
сломаными ресурсами; он не входит в операторский gate. Перенаправления самого
роутера и выключенные функции перечисляются отдельно, а не считаются проверенными
экранами. Apps и другие нужные тесту UI-функции включаются в disposable seed.

Без параметров `npm run route-matrix` проверяет только одностраничную fixture;
она не подтверждает полноту настоящего интерфейса. Для готового тестового сервера:

```sh
npm run route-matrix -- --server-dir <SERVER> --base-url http://127.0.0.1:3310 --company-prefix CMP --output <REPORT>
```

`paperclip-ru report --route-matrix <REPORT>` присоединяет измерения и provenance.
Размер словаря и статические `uncoveredUi` не являются процентом перевода UI.

## Архивы и SVG

Релизная сборка требует чистого Git checkout. После коммита:

```sh
npm run pack:check
npm run release:dry-run
node --input-type=module -e "import {assertSvgAccepted} from './tools/lib/svg-accept.mjs'; await assertSvgAccepted('docs/images');"
```

Тесты могут явно вызвать `buildRelease({testBuild: true, outDir: <TEMP>})`.
Такие архивы помечаются `testBuild=true` и не подходят для публикации.
Обычная сборка не обходит проверку чистоты при внешнем outDir.
