# Translation guide

Практическое руководство по обновлению русской локализации. Канонические
термины находятся в [`GLOSSARY.md`](GLOSSARY.md); правила безопасности и тесты
для изменений — в [`../CONTRIBUTING.md`](../CONTRIBUTING.md).

## Слои и приоритет

Итоговый exact-словарь загружается в таком порядке; более поздний слой
перекрывает предыдущий:

1. `locales/ru.bulk.json` — основной детерминированно отсортированный словарь.
2. `locales/ru.catalog.json` — курируемые общие UI-термины.
3. `locales/ru.manual.json` — небольшой ручной слой единиц и форм.
4. `locales/ru.json` — приоритетные точечные исправления.

После него применяются `no-exact.json`, контекстные `ru.rules.json`, plural и
запрет статической замены из `no-static.json`. Обычную правку формулировки
вносите в `ru.json`; не редактируйте большой `ru.bulk.json` вслепую.

## Процесс после новой версии Paperclip

1. Зафиксируйте точную версию официального npm-пакета и npm integrity.
2. Извлеките кандидатов командами из `tools/`, сохраняя маршрут и исходный
   контекст строки.
3. Отделите операторский UI от библиотек, кода, prompts, идентификаторов и
   пользовательских данных.
4. Сформируйте delta: только новые или действительно изменившиеся строки.
5. Переводите по глоссарию во временном `locales/parts/` либо сразу в
   `locales/ru.json` для небольшого изменения.
6. Проверьте placeholders, пробелы по краям, пунктуацию, `no-exact`,
   `no-static`, scoped rules и plural.
7. Выполните `npm run build`, `npm run lint`, unit, integration и e2e.
8. Для нового bundle обновите `data/fingerprints.json`, затем пройдите
   официальный lifecycle/browser gate в обычном режиме и с panel-resize.
9. Только после byte-identical revert обновите `data/compatibility.json` и
   подготовьте GitHub Release notes.

## Правила строки

- Сохраняйте ведущие и хвостовые пробелы, финальную пунктуацию, HTML/Markdown и
  placeholders (`{{name}}`, `{0}`, `%s`, `$1`, `:id`) без изменений.
- Используйте естественный русский регистр: `New Task` → «Новая задача».
- Кнопки обычно формулируются инфинитивом, вкладки и заголовки —
  существительным, описания — законченным предложением.
- Бренды, имена моделей, API/CLI/JSON, команды, пути, selectors, storage keys и
  названия клавиш не переводятся.
- Примеры кода и значения полей вроде URL, `GITHUB_TOKEN`, `agent-123` или
  `operator.admin` сохраняются исходными.
- Роль, статус или короткий ключ переводите только после подтверждения, что это
  видимая подпись. Неуверенное совпадение безопаснее оставить исходным.
- Инструкции и системные prompts агентов не переводятся: это меняет поведение,
  а не язык интерфейса.
- Пишите «ё»; обращение к пользователю — на «вы» со строчной.

## Временная пакетная работа

`tools/prepare-translation.mjs` может создать chunks в `work/`. Результат блока
имеет вид массива `{"i": 0, "ru": "Перевод"}` и временно сохраняется как
`locales/parts/ru.chunk-<ID>.json`. Индекс `i` относится к позиции в исходном
chunk; пропущенные технические строки в результат не включаются.

`work/`, `locales/parts/`, извлечённые строки, отчёты и материалы ревью не
коммитятся и не входят в GitHub Release. Постоянным результатом являются только
итоговые слои `locales/*.json`, glossary, fingerprints и автоматические тесты.

Покрытие можно сформировать командой
`node tools/paperclip-ru.mjs report --output coverage.json`. Сам размер
`work/missing.json` не является мерой долга операторского UI: в нём много
библиотечных и технических строк.
